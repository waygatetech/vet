Rulings (2026-10-08, Brian): test_command in .vet.yaml; re-lock only when tests globs change; no fail-first requirement. All recommendations accepted.

New package `internal/lock`:
- `Tests(plan []byte) (ticket string, globs []string, err error)` reads `ticket` and `tests` from frontmatter (via `critique.Frontmatter`).
- `Lock{Ticket, Head, Tests []string (globs), Files map[path]sha256}` as JSON at `.vet/locks/<ticket>.json`.
- Files are `git ls-files --cached --others --exclude-standard` filtered with the exported `review.Match` (`**` support).
- `Check` compares the current matched-file set and hashes against the lock, and the plan's globs against the locked globs. It returns the list of differences.

`vet lock --plan p`: if `tests` is empty, exit 2. If `test_command` is unset, exit 2. If a lock exists with the same globs, exit 1 ("already locked; amend the plan's tests to re-lock"). Otherwise write the lock and print its path.
`vet lock --plan p --check`: with no `tests` in the plan, print "no locked tests" and exit 0. With no lock file, exit 1. Any changed/added/removed file or changed globs exits 1. Otherwise run `test_command`, exit 1 if it fails, and exit 0 if it passes.

Tests: table-driven `TestLockExitCodes` in main_test.go (temp git repo), plus unit tests for Check diffs in internal/lock. README gets a short section.
