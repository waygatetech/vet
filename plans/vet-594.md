Rulings (2026-10-08, Brian): deterministic diff gate, not a reviewer check.

Hole: deleting or rewriting the working-tree lock and re-running `vet lock` re-locks edited tests without amending the plan.

Fix: `--check` stops trusting the working-tree lock. It anchors on the committed one.
- `lock.Committed(ctx, base, path) (Lock, bool, error)`: `git merge-base base HEAD`, then `git show <mb>:<path>`. The bool reports whether the lock exists at that commit.
- In `--check`:
  - If there's no committed lock: exit 1. With no working lock either, the message is "not locked". Otherwise it's "commit the tests and lock before implementing".
  - The anchor is the committed lock. If the plan's `tests` globs differ from the anchor's (a plan amendment, which tix re-tiers), the anchor becomes the working-tree lock, which must exist.
  - `Diff(anchor, snapshot)` as today, then `test_command`.
- `vet lock` (write) is unchanged.

Tests: update `TestLockExitCodes` to commit the lock. Add steps for "uncommitted lock blocks" and "deleted + re-locked lock still blocks the edited test". README updated.
